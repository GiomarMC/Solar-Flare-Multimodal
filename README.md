# Solar Flare Multimodal: image-physics complementarity for M- and X-class flare prediction

Replication package for:

> G. D. Muñoz Curi and R. Cardenas Talavera.
> *Image-Physics Complementarity for M- and X-Class Solar Flare Prediction: A Multimodal Study with Swin3D and BiLSTM.*
> SIMBig 2026. Springer, Communications in Computer and Information Science (CCIS).

## Overview

This work compares two modalities on equal footing for predicting solar flares of GOES class M
or above, at 24- and 48-hour horizons:

- **Visual branch**: Swin3D-T over sequences of 16 FITS magnetograms, in physical scale (Gauss).
- **Physical branch**: BiLSTM over 17 SHARP parameters.
- **Late fusion**: weighted ensemble of branch probabilities, and a meta-classifier (stacking).

The headline result is negative and fully documented here: **no late-fusion strategy beats the
stronger individual branch.** Complementarity is real but does not manifest as additive gain.
It shows up instead as distinct operating profiles, better probabilistic reliability on the
physical side, and a horizon-dependent ranking.

Four ablation studies, each self-contained, examine why.

## What is and is not included

| Included | Size |
|---|---|
| Training, evaluation and analysis code | 400 KB |
| Model logits and labels, all models and folds | 4.6 MB |
| Text reports with the published numbers | 68 KB |
| SHARP parameter complement downloaded from the JSOC | 6.2 MB compressed |

| Not included | Why |
|---|---|
| Model checkpoints (about 31 GB) | Regenerated by retraining; not needed to verify results |
| Base dataset (23 GB) | Third-party, distributed by its authors (see [Data](#data)) |
| FITS magnetograms (hundreds of GB) | Downloaded from the JSOC with the scripts provided |

**The logits are the important part.** They are the raw outputs of every trained model on
every fold and horizon. With them you can recompute every table, statistic and figure in the
paper in minutes, on a laptop, without a GPU and without downloading the dataset.

## Prerequisites

### To reproduce the analysis (recommended starting point)

| Requirement | Detail |
|---|---|
| Python | 3.9 or newer. Developed and tested on 3.13 |
| Operating system | Linux. Nothing is platform specific, but only Linux was tested |
| Packages | numpy, scipy, scikit-learn, matplotlib, PyYAML, tqdm and PyTorch |
| Disk | About 12 MB, the repository itself |
| GPU | Not needed. PyTorch is required because the bootstrap routines are vectorised with it, but a CPU-only build is enough |
| Time | Seconds to a few minutes per script. Bootstrap runs use B = 10000 resamples and take longer |

### To retrain the models

| Requirement | Detail |
|---|---|
| GPU | CUDA-capable. Published models were trained on an NVIDIA RTX 3060 with 6 GB of VRAM |
| Packages | The above, plus torchvision and PyTorch Lightning, and a CUDA build of PyTorch |
| Disk | About 25 GB for the base dataset, several hundred GB if you download the FITS magnetograms, plus room for checkpoints |
| Time | The physical branch is cheap: the full 5-fold cross-validation over both horizons takes roughly 15 minutes. The visual branch is the expensive part, several hours per fold on a 6 GB GPU |

The 6 GB VRAM limit is why the visual encoder is the Swin3D **tiny** variant. Larger variants
were not explored, and this is stated as a limitation in the paper.

### To rebuild the dataset from scratch

Additionally requires `astropy` and `drms`, plus a registered email address for JSOC export
requests. Expect long queue times.

## Installation

```bash
git clone https://github.com/GiomarMC/Solar-Flare-Multimodal.git
cd Solar-Flare-Multimodal

python -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` is split into three blocks: analysis, training and data rebuilding. If you
only intend to reproduce the analysis, the first block is sufficient.

Note that the first block includes PyTorch. The bootstrap routines are vectorised with it, so
it is needed even without a GPU. A CPU-only build works and is much smaller:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

## Quick start: reproduce the results without a GPU

This is the fast path. It uses the logits shipped in `results/logits/` and needs no dataset.

```bash
# Per-branch metrics with confidence intervals (stratified bootstrap, B = 10000)
python analysis/bootstrap_ci.py

# Paired comparisons between branches and fusion strategies
python analysis/bootstrap_paired.py

# Fixed combination rules (mean, product, maximum, minimum)
python analysis/late_fusion_rules.py

# Meta-MLP stacking, 5 folds
python analysis/stacking_5fold.py

# Probabilistic calibration and Brier Skill Score
python analysis/bss_calibration.py

# Structural ceiling of decision-level fusion
python analysis/diversidad_ramas.py

# Full metric table for every variant
python analysis/metricas_variantes.py
```

Reports are written to `results/reports/`.

### Built-in verification

Several scripts carry **self-checks against the published values**. They print `OK` or
`DIFIERE` next to the relevant rows. For example, `metricas_variantes.py` verifies that the
BiLSTM-17 at 48 h reproduces POD 0.903, FAR 0.653, HSS 0.464 and F1 0.499, and that the visual
branch reproduces POD 0.985, FAR 0.752, HSS 0.348 and F1 0.394.

If those controls print `OK` on your machine, your environment reproduces the paper.

## Data

Three pieces are involved. Only the third is in this repository. Full detail in
[`data/README.md`](data/README.md).

### 1. Base dataset, not included

From Grim and Gradvohl (2024), CC BY 4.0:

- Zenodo: https://doi.org/10.5281/zenodo.10246577 (`SFF_Magnetogram_Seq_MViTs.zip`, 23.1 GB)
- Original code: https://github.com/lfgrim/SFF_MagSeq_MViTs

It provides the chronological 5-fold partition, the labels at both horizons, the 16-frame
sequence files, and magnetograms as 8-bit JPEG. **This work reuses only the partition and the
labels**; both the images and the SHARP parameters were rebuilt.

After unpacking, point an environment variable at it:

```bash
export SFMM_DATA=/path/to/SFF_MagSeq_MViTs
```

Every script and config refers to `${SFMM_DATA}`. There are no absolute paths in the code.

### 2. FITS magnetograms, not included

8-bit JPEG discards the physical scale of the field in Gauss along with its dynamic range, so
the visual branch works from the original FITS files instead:

```bash
python scripts/download_jsoc_fits.py
python scripts/preprocess_fits_to_npy.py
```

Each frame is clipped to the standard HMI/SHARP saturation of +-500 G, normalised to [-1, 1],
replicated to 3 channels and resized to 224 x 224.

### 3. SHARP parameter complement, included

The base dataset ships 10 numerical attributes and **omits the single most influential
predictor, TOTUSJH**, as well as TOTUSJZ and R_VALUE. This work downloaded the JSOC series
`hmi.sharp_720s` to complete a set of 21 parameters, of which the paper uses 17.

That file is included because regenerating it costs hours of JSOC queries:

```bash
gunzip -k data/para_flare_21params.txt.gz
mv data/para_flare_21params.txt "$SFMM_DATA"/
```

It holds 73,810 rows, one per magnetogram.

## Retraining

```bash
export SFMM_DATA=/path/to/SFF_MagSeq_MViTs

# Visual branch
python scripts/train_swin3d_standalone_fits.py --config configs/swin3d_standalone_fits_48h.yaml

# Physical branch, one fold
python scripts/train_lstm_standalone.py --config configs/lstm_cv_48h_k0.yaml

# Extract logits for every fold and horizon
python scripts/save_logits_swin3d.py
python scripts/save_logits_lstm.py
```

Add `--smoke 5` to any training script for a short sanity pass that runs in under a minute.

**Protocol.** Chronological 5-fold cross-validation with a fixed test set of 9,384 sequences
(the most recent block). The decision threshold is swept on each fold's validation split and
applied to test without re-tuning. Class imbalance is handled with weighted random sampling
plus a positive-class weight of 10.0 during training and 38.0 during validation.

## Ablation studies

Each study lives in its own directory with a README stating the question, how to run it, the
numbers and the conclusion.

| Study | Question | Verdict |
|---|---|---|
| [`01_recurrent_architecture`](studies/01_recurrent_architecture/) | Is the physical branch limited by its recurrent architecture? | No. Skill is flat across 120 training runs |
| [`02_sharp_provenance`](studies/02_sharp_provenance/) | Which SHARP parameters are computed from the same magnetogram the visual branch sees? | 5 of 17. The other 12 require the vector field |
| [`03_los_derived_ablation`](studies/03_los_derived_ablation/) | If those 5 are removed, does fusion start to help? | No. Redundancy comes from a common physical cause, not from derivation |
| [`04_feature_selection_leakage`](studies/04_feature_selection_leakage/) | Did the feature pre-selection leak information from the evaluation periods? | The selection is stable across folds, with one borderline exception |

Study analyses run from the included logits and need no GPU. Retraining the variants does.

## Logits format

Files follow the pattern `{model}_{horizon}h_k{fold}_{split}.npz`.

| Model key | Description |
|---|---|
| `swin3d` | Visual branch over FITS |
| `swin3d_jpeg` | Visual branch over the base dataset's 8-bit JPEG |
| `lstm` | Physical branch, 17 SHARP parameters. The published model |
| `lstm21` | All 21 parameters, no pre-selection |
| `lstm16` | The 16 vector parameters, dropping the LoS-derived ones |
| `lstm12` | The 12 vector parameters of the original selection |
| `lstm16b` | The published 17 minus MEANGBZ |

Each file stores `logits` and `labels`:

```python
import numpy as np
d = np.load("results/logits/lstm_48h_k0_test.npz")
logits, labels = d["logits"], d["labels"]
```

Logits are raw, before the sigmoid. Apply `1 / (1 + exp(-x))` for probabilities.

## Notes and caveats

- Bootstrap scripts use a fixed seed, so results are reproducible run to run. Small differences
  across machines can still appear from BLAS and floating-point ordering; the self-checks use a
  tolerance of 5e-4.
- Training is not bit-for-bit reproducible across GPUs. The published logits are provided
  precisely so that the analysis does not depend on reproducing training exactly.
- The data covers a single solar cycle, the rise and maximum of Cycle 24. Generalisation to the
  declining phase or to Cycle 25 is untested, and is stated as a limitation in the paper.
- Code comments and the ablation study reports are in Spanish. Identifiers, this README and the
  paper are in English.
